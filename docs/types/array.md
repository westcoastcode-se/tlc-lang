# Arrays

[Index](../README.md) · [Previous: Unions](union.md) · [Next: Enums](enum.md) · [Cost](../cost.md) · [Grammar](../grammar.md)

An array length is a positive decimal `i32` literal. `[_]i32{10, 20, 12}` writes the values. `_` stands for the length, which is the number of values, so the type is `[3]i32`. A file-scope array takes the same lists, including a struct element: `var named [3]i32 = {10, 4, 1}`, `var row = [_]i32{10, 20, 12}`, and `var origin = [_]Point{Point{.x = 1, .y = 2}}`.

An element that is an array is another brace list, or a value of that array. `var row [2][3]i32 = {{1, 2, 3}, {4, 5, 6}}` stores those values, and `row[1][2]` is 6. `var inner [2]i32 = {1, 2}` then `var row = [_][2]i32{inner}` copies `inner`. `{a, b}` copies both rows when `a` and `b` are `[2]i32`. `grid[1]` and `give()` copy that row the same way. A later store into the source does not change the copy. A different length, `[_][3]i32{inner}`, is reported as `type mismatch: expected [3]i32, found [2]i32`. A parameter `[2]i32` in that list copies the array. A later store into the parameter does not change the copy. A different length, `[_][3]i32{row}`, is reported as `type mismatch: expected [3]i32, found *i32`. `var grid = [_][2][3]i32{{{1, 2, 3}, {4, 5, 6}}}` is one outer element of `[2][3]i32`, and `grid[0][1][2]` is 6. `{[_]i32{1, 2, 3}, [_]i32{4, 5, 6}}` writes the same rows. A different count is reported as `type mismatch`. `[_][]i32{{1, 2}, {3}}` is reported as `type mismatch`.

```c
func add4(p *i32) i32 {
    return p[0] + p[1] + p[2] + p[3];
}

func main() i32 {
    var a [4]i32;
    a[0] = 10;
    a[1] = 20;
    a[2] = 7;
    a[3] = 5;
    return add4(a);
}
```

The array becomes a pointer when it is passed. A string literal is `[]const u8`. It can be passed to `[]const u8` and to `*const u8`. It cannot be passed to `*u8` or `[]u8`. The index has type `i32`. `new [n]i32` reserves `n` elements and yields `*i32`. `buf[i] = 1` writes an element. `new [n]Point{{.x = 1}...}` stores that value in every element. `new [_]Point{{.x = 1}, {.y = 2}}` is `*[2]Point`. See [Builtin](../builtin/allocator.md).

`[]T` is a readonly slice of an array. `var v []i32 = row` takes a slice of `[N]i32`. `row[i:j]` takes the elements from `i` up to, but not including, `j`, and so does `v[i:j]`. A missing low bound is `0`. A missing high bound is the length. `row[i:]`, `row[:j]`, and `row[:]` are those slices. A range of `[_][2]i32` is a slice of `[2]i32`. The length counts rows. `v[i]` reads an element, and `v[i] = 1` is reported as `type mismatch`. `v.len` is `i32`. `row.len` on a sized array is `i32`, the number of elements, with the same spelling. An empty array has length 0. The length is a compile-time integer. At file scope, `const N = row.len` can be an array length. Assigning `row.len`, or taking its address, is reported as `not an lvalue`. `sizeof([]T)` is 16. A slice parameter stays a slice. `a.len` in `func take(a [3]i32)` is 3, the length that was written. The parameter is still a pointer, so `return a` where a slice is expected is reported as `return type: expected []i32, found *i32`.

A field may be a slice, `items []i32`. It is stored as the slice header. `sizeof` of `{ n i32; items []i32; }` is 24. Assigning the field replaces that header. The same field in `extern(abi="c")` is reported as `not supported yet`.

`var row = [_]i32{10, 20}` has type `[2]i32`. Reading that name decays to `*i32`, so `var copy = row` is `*i32`. `copy = row` is reported as `not an lvalue`. Writing the array type copies the value. `var copy [2]i32 = row` stores both elements in a new array. A later store into `row` does not change `copy`. `const held = [_]i32{8, 9}` copies the same way, `const frozen [2]i32 = held`. A different length, `var copy [3]i32 = row`, is reported as `type mismatch`. A parameter `[2]i32` is a pointer. `var copy [2]i32 = row` copies those elements. A later store into the parameter does not change the copy. `var copy = row` stays `*i32`. Assigning the written array, `kept = row`, is reported as `not an lvalue`. A different length, `var copy [3]i32 = row`, is reported as `type mismatch: expected [3]i32, found *i32`. `var from_file [3]i32 = file_row` copies a file-scope array into a local. `var copy [2]i32 = give()` copies the array when `give` returns `[2]i32`. `var grid = [_][2]i32{{1, 2}, {3, 4}}` then `var whole [2][2]i32 = grid` copies both rows, and `var line [2]i32 = grid[1]` copies that row. A file-scope `var copy [2]i32 = row` copies that array into the binary. A later store into `row` does not change `copy`. `const frozen [2]i32 = held`, `var whole [2][2]i32 = grid`, and `var line [2]i32 = grid[1]` copy the same way. `var copy [2]i32 = give()` and `var copy [2]i32 = unsafe give()` run that call before `main`. A source that is not a constant array in this file, and not a call, is reported as `global initializer is not a constant`. An element copies the same way. `var row = [_][2]i32{inner}` copies that array. `const inner = [_]i32{1, 2}` before that var is that copy. `[_][2]i32{grid[1]}` copies that row. `var row = [_][2]i32{give()}` and `var row = [_][2]i32{unsafe give()}` run that call before `main`. `var row = [_]i32{give(), 2}` and `var row [2]i32 = {give(), 2}` run `give` before `main` when `give` returns `i32`. Each element is stored before the next one runs, so that call reads the elements already stored. `[_]Point{give()}` stores that value. `unsafe give()` is that call. A `const` with that call, `[_]i32{n + 1}`, `[_]i32{give() + 1}`, a name whose initializer is a call, and an index whose bound does not fold, are reported as `global initializer is not a constant`. `var row = [_][2]i32{inner}` before `const inner` is reported as `undeclared identifier`. `return row` returns the local array. `return give()` returns that array when `give` returns `[2]i32`. `return grid[1]` returns that row. `return [_]i32{4, 6}` returns that list. `return file_row` returns the file-scope array. `return {4, 6}` returns that list. `return {{1, 2}, {3, 4}}` returns that array. A different count, `return {4}`, is reported as `type mismatch`. `return {inner, other}` copies those rows when the result is `[2][2]i32`. `return {inner}` when the result is `[2]i32` is reported as `type mismatch`. A parameter `[2]i32` in that list copies the array. `return row` when `row` is a parameter `[2]i32` and the result is `[2]i32` copies those elements. `return grid` when `grid` is a parameter `[2][2]i32` and the result is `[2][2]i32` copies both rows. `grid[i]` on that parameter is that row, so `return grid[1]` copies it and `grid[1][0]` reads one element. `return cube[1]` when `cube` is a parameter `[2][2][2]i32` and the result is `[2][2]i32` copies that plane. `cube[1][0][1]` reads one element. `p[i]` when `p` is `*[2]i32` is still `(*p)[i]`. `return {a, b}` copies those parameter rows when the result is `[2][2]i32`. Passing that parameter to a function that takes `[N]T` passes the pointer. `return row` where `[]i32` is expected is reported as `return type: expected []i32, found *i32`. A different length is reported as `return type: expected [3]i32, found *i32`. `return grid` where `[3][2]i32` is expected is reported as `return type: expected [3][2]i32, found *[2]i32`. `return {row}` when the result is `[2]i32` is reported as `type mismatch`.

## Cost

`var a [2]i32` with no initializer adds no instruction. The elements are uninitialized. `row.len` is the constant element count. `func main() i32 { var row [3]i32; return row.len; }` executes 2 instructions, `movl $3, %eax` and `retq`. The array is not read. `var row [3]i32 = {10, 20, 12}` stores those three values and does not store a zero first. `var row [2][3]i32 = {{1, 2, 3}, {4, 5, 6}}; return row[1][2];` is 8 instructions: six `movl` of the elements, one `movl` of `row[1][2]` into `%eax`, and `retq`. The array is not zeroed first. `var grid = [_][2][3]i32{{{1, 2, 3}, {4, 5, 6}}}; return grid[0][1][2];` is the same 8. A file-scope `var row = [_][2][3]i32{{{1, 2, 3}, {4, 5, 6}}}` keeps those six values in the binary. `return row[0][1][2]` is 2 instructions, one `movl` of that element and `retq`. A file-scope `var copy [2]i32 = row` keeps both elements in the binary and adds no instruction. `return copy[1]` is 1 `movl` and `retq`. `var row = [_][2]i32{inner}` keeps that row in the binary and adds no instruction. `return row[0][1]` is 1 `movl` and `retq`. `var row = [_][2]i32{give()}` runs before `main`. `return row[0]` is 1 `movl` and `retq`. The call and the stores run in `tlc.init`: 44 instructions on the path where the trace holds fewer than 32 frames. `give`, returning a local `[2]i32`, is 5 instructions. `var row = [_][2]i32{unsafe give()}` is that same `tlc.init`. `var row = [_]i32{give()}` runs before `main` when `give` returns `i32`. `return row[0]` is 1 `movl` and `retq`. The call and the store run in `tlc.init`: 37 instructions on the path where the trace holds fewer than 32 frames. `give`, returning the constant 4, is 2 instructions. `unsafe give()` is that same `tlc.init`. `var row = [_]i32{give(), 2}` and `var row [2]i32 = {give(), 2}` are 38 instructions in that `tlc.init`. The extra instruction stores 2. `var line [2]i32 = grid[1]` and `const frozen [2]i32 = held` are that same copy. `var copy [2]i32 = give()` runs before `main`. `return copy[0]` is 1 `movl` and `retq`. The call and the stores run in `tlc.init`: 44 instructions on the path where the trace holds fewer than 32 frames. `give`, returning a local `[2]i32`, is 5 instructions. `var copy [2]i32 = unsafe give()` is that same `tlc.init`. `a[1] = 3` on a local, with a constant index, is 1 `movl` into the element's slot. Reading it back is 1 `movl`. A variable index on a pointer is a sign-extend and a scaled load. `return p[i]` is 8 instructions including the pointer store, the index store, a second sign-extend, and `retq`.

Passing `[4]i32` to a function is 1 `leaq` of the first element, plus the traced call. The callee receives a pointer. `return a[0]` there is 4 instructions including the pointer store and `retq`. The elements are not copied. `return a.len` is 3 instructions: the pointer store, 1 `movl` of the written length, and `retq`. The array is not read. `return a[0:2]` is 4: the store, 1 reload of the pointer, 1 `movl` of the length 2, and `retq`. `return a[1:]` is 5: those, plus 1 `addq` of 4.

Returning `[2]i32` from a local puts the two elements in `%eax` and `%edx`. Storing both elements and returning is 5 instructions. The local is not zeroed first. `var copy [2]i32 = row` is 4 instructions after `row` is stored: two `movl` loads and two `movl` stores. The slot is not zeroed first. `var row = [_][2]i32{inner}` is those same 4 after `inner` is stored. `var grid [2][2]i32 = {a, b}` is 8 instructions after `a` and `b` are stored: four `movl` loads and four `movl` stores. The slot is not zeroed first. `return copy[1]` is 1 `movl` and `retq`. `var line [2]i32 = grid[1]` is those same 4 after `grid` is stored. `var copy [2]i32 = give()` pays the traced call. `give`, returning a local `[2]i32`, is 5 instructions. After `callq`, 1 `movl` keeps the low element and 2 `movl` store the pair. The copy into `copy` is 8 `movl`: the loaded pair is stored in a temporary and stored again. `return copy[1]` is 1 `movl`, then `addq` and `retq`. `return grid[1]` is 2 `movl` into `%eax` and `%edx`, then `retq`, after `grid` is stored. `return [_]i32{4, 6}` is those same 5 as returning a local. `return {4, 6}` is those same 5. `return {{1, 2}, {3, 4}}` is 14 instructions: four `movl` store the elements, four `movl` reload them, four `movl` store them through the return pointer, one `movq` copies that pointer, and `retq`. The array is not zeroed first. Returning a local `[2][2]i32` of that list is those same 14. `return {a, b}` when `a` and `b` are `[2]i32` is 22 instructions: one `movq` copies the return pointer, four `movl` store `a` and `b`, eight `movl` copy those rows into a temporary, four `movl` reload that temporary, four `movl` store them through the return pointer, and `retq`. The array is not zeroed first. `return give()` pays the traced call. After `callq`, 1 `movl` keeps the low element and 2 `movl` store the pair. Returning that pair is 4 `movl` into a temporary and 2 `movl` into `%eax` and `%edx`, then `addq` and `retq`. On the path where the trace holds fewer than 32 frames, that function is 42 instructions. `return row` when `row` is a parameter `[2]i32` is 5 instructions: the pointer store, one reload, two `movl` into `%eax` and `%edx`, and `retq`. `return grid[1]` when `grid` is a parameter `[2][2]i32` is 5: the pointer store, one reload, and two `movl` of that row. `return grid` for that parameter is 12: one `movq` copies the return pointer, the source pointer is stored and reloaded, four `movl` load the elements, four `movl` store them through the return pointer, and `retq`. The array is not zeroed first. `return grid[1][0]` is 4: the pointer store, one reload, one `movl` of that element, and `retq`. `return cube[1]` when `cube` is a parameter `[2][2][2]i32` is those same 12, loading the second plane. `return cube[1][0][1]` is 4: the pointer store, one reload, one `movl` of that element, and `retq`. `var copy [2]i32 = row` when `row` is a parameter `[2]i32` is 5 instructions after the pointer is stored: one reload, two `movl` loads, and two `movl` stores. The slot is not zeroed first. `return copy[1]` is 1 `movl` and `retq`. `var grid = [_][2]i32{row}` is those same 5 after the pointer is stored. `return {a, b}` when `a` and `b` are parameter `[2]i32` is 22 instructions: one `movq` copies the return pointer, two `movq` store the pointers, each row is one reload and four `movl`, four `movl` reload that temporary, four `movl` store them through the return pointer, and `retq`. The array is not zeroed first.

`new [n]i32` is the allocation counted on [new and delete](../statements/new.md). There is no bounds check on an index, so the index adds no compare.
