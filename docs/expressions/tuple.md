# Tuples and lists

[Index](../README.md) · [Previous: Unsafe](unsafe.md) · [Next: Statements](../statements/block.md) · [Cost](../cost.md) · [Grammar](../grammar.md)

`(40, 2)` is a tuple. The element types are the types of the values before promotion, so `(40, 'a')` is `i32` and `u8`. `(40)` is the value `40`. `type Duo (i32, i32)` names that tuple. `Duo` is a different type from `(i32, i32)`, so the value is `Duo((40, 2))`. `type Something[K type, V type] (K, V)` is that alias. `Something[i32, i32]((40, 2))` names one specialization. `type Something[K, V] (K, V)` is `expected a type` on the comma. A parameter may be written `(i32, i32)`. A generic parameter `(P1, P2)` is that tuple. `SomeFunc[i32, i32](0, (40, 2))` writes the types. `SomeFunc(0, (40, 2))` infers them. An element may be an array: `value[0][1]` reads one element, and the elements are kept when the tuple is passed or cast. A function type keeps that array. `func () (([2]i32, i32))` and `func (([2]i32, i32)) i32` match the function that returns or takes `([2]i32, i32)`. `var n (i32)` is `i32`. `var value (i32, i32) = (40, 2)` is that tuple. `func pair() ((i32, i32))` returns that tuple. `return (40, 2)` matches it. `return 40, 2` does not. `func pair() (i32, i32)` is still two results. `var op func () ((i32, i32)) = pair` stores that function. `var value = op()` binds the tuple, and `value[0] + value[1]` is 42. `func () (i32, i32)` is still two results. `var op func () ((i32, i32), i32) = pair` stores that function. `var value, n = op()` unpacks the call, and `value[0] + value[1] + n` is 42. `func ((i32, i32)) i32` is one tuple parameter. `var op func ((i32, i32)) i32 = take` stores `take` when `take` takes `(i32, i32)`, and `op((40, 2))` calls it. `op(40, 2)` is `argument count`. `func (i32, i32) i32` is still two parameters. A function of two `i32` parameters does not match, and that assignment is `type mismatch`. `op(Duo((40, 2)))` is `type mismatch`, because `type Duo (i32, i32)` is a different type. `func ((i32, i32), i32) i32` is that tuple beside another parameter. `var op func ((i32, i32), i32) i32 = take` stores `take` when `take` takes `(i32, i32)` and an `i32`, and `op((40, 1), 1)` calls it. `func (i32, (i32, i32)) i32` is that tuple as another parameter. `op((40, 1))` is `argument count`. `op(40, 2)` is `type mismatch`. A function of three `i32` parameters does not match, and that assignment is `type mismatch`. `op(Duo((40, 1)), 1)` is `type mismatch`, because `type Duo (i32, i32)` is a different type. `func pair() ((i32, i32), i32)` is that tuple beside another result. `return (40, 2), 0` matches it. `return 40, 2, 0` is `return type: expected 2 results, found 3`. A field may be written `value (i32, i32)`. `box.value = (40, 2)` stores it, and `box.value[0]` reads an element. `sizeof(Duo)` is the size of the alias. `[2]Duo` is an array of it. `row[0] = Duo((40, 2))` stores one element, and `row[0][0]` reads one field. A tuple does not convert to a slice. `row[0:2]`, `row[:]`, the same range of a parameter `[N]Duo` or `[N][M]Duo`, and `p[0:2]` on `*[N]Duo` are `type mismatch`. `[]Duo` and `[][N]Duo` are `not supported yet`. `var value = (40, 2)` and `value := (40, 2)` each bind that tuple. `var value1, value2 = value` and `a, b := value` unpack it, one name per element. `var value1, value2 = (40, 2)` unpacks the literal the same way. The number of names matches the tuple. A different count is reported as `type mismatch`. `value[0]` reads one element. The index is a constant. `typeof(value)` is that tuple's type. `typeof(value).fields()[i].kind` is the type of element `i`, and `typeof(value[i])` is the same type. `builtin.fmt` copies `{0}` and `{1}` from a compile-time tuple into one `[]const u8`. A string element is its text. An integer element is decimal. `{{` and `}}` are the brace characters. A `var` element is `not supported yet`. A macro can `emit printf` of that text, so `print_with_tuples("Hello {0}! {0} is {1} years old", ("John Doe", 26))` is `printf("Hello John Doe! John Doe is 26 years old")`.

`{10, 20, 12}` fills an array. Where a struct is expected, that brace list is reported as `type mismatch`. An empty `{}` names no fields. `Point{}` names the struct, so the type is `Point`. Each field takes the value written on it, and stays uninitialized when the field has none. `Point{0...}` stores 0 in every field. `{1, 2, 0...}` stores 0 in the rest of an array whose length is known.

`[_]i32{10, 20, 12}` is an array value. `_` stands for the length, which is the number of values, so the type is `[3]i32`. `var row = [_]i32{10, 20, 12}` and `row := [_]i32{10, 20, 12}` have that type. `row[0]` reads an element. An empty `[_]i32{}` has length 0. `[_][2]i32{{1, 2}, {3, 4}}` is a nested brace list, and `grid[0][1]` reads an element. `[_][2][3]i32{{{1, 2, 3}, {4, 5, 6}}}` is the next array, and `grid[0][1][2]` reads an element. At file scope the same literal initializes the variable when each value is a constant. `const fixed = [_]i32{19, 2}` is that array, and a store of an element is reported as `type mismatch`. `[]i32{10, 20, 12}` is reported as `expected '_'`. A slice is a separate type, `var v []i32 = row`. `v[i]` reads an element and is reported as `type mismatch` when used as the target of `=`. `v.len` is `i32`. `row.len` on the array is `i32`, the number of elements. `row[i:j]` and `v[i:j]` are the elements from `i` up to, but not including, `j`. The result is a slice. A missing low bound is `0`. A missing high bound is the length.

```c
func main() i32 {
    var row = [_]i32{10, 20, 12};
    return row[0] + row[1] + row[2];
}
```

```c
func main() i32 {
    var value = (40, 2);
    var value1, value2 = value;
    a, b := (7, 'a');
    value1, value2 = (1, 2);
    var row [3]i32 = {10, 20, 12};
    return value[0] + value1 + a + row[2] + b;
}
```

## Cost

`(40, 2)` stored in a local is 2 `movl` instructions, one per element. `value[0]` is 1 load. The index is constant, so there is no multiply. `var value Duo = Duo((40, 2)); return value[0] + value[1];` is 6 instructions: two stores, two loads, `addl`, and `retq`. `var value Something[i32, i32] = Something[i32, i32]((40, 2)); return value[0] + value[1];` is those same 6 instructions. `var value (i32, i32) = (40, 2); return value[0] + value[1];` is those same 6 instructions. `func pair() ((i32, i32)) { return (40, 2); }` is 3 instructions: `movl $40, %eax`, `movl $2, %edx`, and `retq`. The caller `var value = pair(); return value[0] + value[1];` is 43 instructions when the trace holds fewer than 32 frames. `var op func () ((i32, i32)) = pair; var value = op(); return value[0] + value[1];` is 48 instructions in `main` on that path. The callee is those same 3 instructions. `var op func () ((i32, i32), i32) = pair; var value, n = op(); return value[0] + value[1] + n;` is 52 instructions in `main` on that path. The callee is those same 4 instructions. `return (40, 2), 0` from `func pair() ((i32, i32), i32)` is 4 instructions: `movl $40, %eax`, `movl $2, %edx`, `xorl %ecx, %ecx`, and `retq`. `var value, n = pair(); return value[0] + value[1] + n;` is 47 instructions in `main` on that path. A field `value (i32, i32)`, assigned `(40, 2)` and returned as `box.value[0] + box.value[1]`, is those same 6 instructions. `return sizeof(Duo)` when both elements are `i32` is 2 instructions: `movl $8, %eax` and `retq`. `var row [2]Duo; row[0] = Duo((40, 2)); row[1] = Duo((1, 1)); return row[0][0] + row[1][1];` is 9 instructions: four `movl` stores, three loads, `addl`, and `retq`. `Duo((40, 2))` adds none. A parameter `(i32, i32)` whose body is that sum is those same 6 instructions. `return SomeFunc[i32, i32](0, (40, 2))`, when the body is `value + other[0] + other[1]`, is 40 instructions in `main` when fewer than 32 frames are stored, and 9 in the specialized function: three stores, three loads, two `addl`, and `retq`. The same concrete function is that same count. `return typeof(row).fields().len` on `var row = ("hi", 26)` is 2 instructions: `movl $2, %eax` and `retq`. `builtin.fmt` of two constant elements adds no instructions of its own: `emit printf` of that text is one traced `printf` of the finished string. `var op func ((i32, i32)) i32 = take; return op((40, 2));` executes 43 instructions in `main` when fewer than 32 frames are stored. The callee `return value[0] + value[1]` is 6 instructions: two stores of the tuple fields, two loads, `addl`, and `retq`. `var op func ((i32, i32), i32) i32 = take; return op((40, 1), 1);` executes 44 instructions in `main` on that path. The callee `return value[0] + value[1] + n` is 8 instructions: three stores, two loads, two `addl`, and `retq`.

Unpacking two `i32` results from a call stores both return registers. After `pair` returns, that is 1 `movl` of `%eax` and 1 `movl` of `%edx` into the two locals, on top of the traced call. The callee that returns `x + y, x` is 7 instructions including its parameter stores and `retq`.

An array brace list stores one immediate per named element. `var row [3]i32 = {10, 20, 12}; return row[0] + row[1] + row[2];` is 7 instructions: three `movl`, one `movl` into `%eax`, two `addl`, and `retq`. A shorter list leaves the tail unstored. `{10, 20, 0...}` on a `[4]i32` stores 0 in every element and then stores 10 and 20. Returning the sum of the four elements is 11 instructions: four `movl` of 0, two `movl` of the named values, one `movl` into `%eax`, three `addl`, and `retq`. A slice built from that array is the header cost on [Slices](../types/slice.md).
